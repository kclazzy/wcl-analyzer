# Сравнение ротации WCL

Программа сравнивает ваш бой из Warcraft Logs с медианой Top 25 игроков того же спека на том же боссе. Результат — Excel-отчёт с графиками: чем ваш лог отличается от повторяющегося паттерна топа, насколько это надёжно и что тренировать первым.

## Две версии: для ПК и для телефона

| | Windows (ПК) | Android (телефон) |
| --- | --- | --- |
| Файл | `WCL Analyzer.exe` | `wclanalyzer-….apk` |
| Нужен Python | нет, всё внутри | нет, всё внутри |
| Нужен интернет | да, для загрузки логов WCL | да, для загрузки логов WCL |
| Где хранятся данные | браузер на ПК и папка `%LOCALAPPDATA%\WCL Analyzer` (кэш) | память приложения на телефоне |
| Куда сохраняется Excel | папка «Загрузки» | «Загрузки/WCL Analyzer» |
| Сервер, хостинг, включённый ПК | не нужны | не нужны |

Обе версии работают самостоятельно и бесплатно: анализ считается на самом устройстве. Ключ Warcraft Logs API каждый вводит свой.

### Как получить файлы

Готовые `.exe` и `.apk` собирает бесплатный GitHub Actions: на этом компьютере их собрать нельзя, `.exe` собирается на Windows, а APK — с Android SDK.

1. Зарегистрируйтесь на https://github.com и создайте репозиторий: **New repository**, любое имя.
2. Загрузите в него все файлы из архива: **uploading an existing file** → перетащите содержимое папки, включая скрытую папку `.github`. Если её не видно, включите показ скрытых файлов.
3. Откройте вкладку **Actions**: сборка запустится сама. Windows-версия собирается около 5 минут, Android — 30–40 минут в первый раз, дальше быстрее.
4. Когда появится зелёная галочка, откройте запуск → внизу **Artifacts** → скачайте `WCL-Analyzer-Windows` и `WCL-Analyzer-Android`.

Чтобы файлы появились в разделе **Releases** с постоянной ссылкой, создайте тег версии: **Releases → Draft a new release → тег `v1.0.0`**.

### Установка на ПК (Windows)

1. Запустите `WCL Analyzer.exe` двойным щелчком.
2. Windows может показать «Система Windows защитила ваш компьютер», потому что у программы нет платной цифровой подписи. Нажмите **Подробнее → Выполнить в любом случае**.
3. Откроется окно с подсказкой и страница программы в браузере. Окно не закрывайте, пока пользуетесь программой.

### Установка на телефон (Android 7 и новее)

1. Скопируйте `.apk` на телефон или скачайте его прямо на телефоне со страницы GitHub.
2. Откройте файл. Android попросит разрешить установку из этого источника: разрешите. Это обычный шаг для приложений не из Google Play.
3. Откройте «Разбор WCL» и подключите свой ключ API или вставьте ссылку переноса с ПК: окно ключа → «Есть ссылка переноса с другого устройства?».

В приложении Excel и резервные копии сохраняются в «Загрузки/WCL Analyzer», а ссылки на Warcraft Logs открываются в браузере телефона.

### Перенос данных между ПК и телефоном

- **Ключ, настройки и 2 последних эталона.** На ПК: «На другом устройстве» → «Скопировать ссылку» → отправьте её себе на телефон. В приложении: окно ключа → «Есть ссылка переноса…» → вставьте.
- **С телефона на ПК, всё целиком.** В приложении: «Сохранить в файл» → файл появится в «Загрузках» телефона → перенесите его на ПК → «Загрузить из файла».
- Загрузка резервной копии из файла внутри Android-приложения недоступна. Переносите данные на телефон ссылкой.

### iPhone

Для iPhone отдельного приложения нет: установить его можно только через App Store, а это платный аккаунт разработчика. На iPhone можно открыть веб-версию (см. «Бесплатно на телефоне и ПК») или пользоваться ПК-версией дома через Wi-Fi.

## Быстрый старт без сборки (Python)


1. Установите Python 3.10 или новее: https://www.python.org/downloads/ (на Windows отметьте «Add python.exe to PATH»).
2. Распакуйте архив и запустите файл двойным щелчком:
   - Windows — `start_windows.bat`;
   - macOS — `start_mac.command` (при первом запуске: правый щелчок → «Открыть»);
   - Linux — `start_linux.sh`.
3. Откроется страница в браузере. Нажмите «Подключить ключ API» и вставьте свой ключ (ниже — как его получить). Ключ сохраняется в браузере.
4. Вставьте ссылку на свой отчёт, нажмите «Найти бой», выберите игрока и нажмите «Разобрать бой».

Первый запуск готовит окружение около минуты. Окно консоли не закрывайте, пока пользуетесь программой: в нём работает интерфейс. Разборы и Excel-файлы сохраняются в истории разборов в браузере, скачать Excel можно кнопкой на странице.

Попробовать без ключа: ссылки «разбор игрока» и «разбор рейда» под полем ввода (демо-данные).

### Ключ Warcraft Logs API

1. Откройте https://www.warcraftlogs.com/api/clients и войдите.
2. Нажмите **Create Client**: имя — любое, Redirect URL — `http://localhost`.
3. Скопируйте Client ID и Client Secret в окно «Подключить ключ API». Программа проверит ключ и запомнит его в этом браузере.

Для командной строки ключ по-прежнему можно указать в файле `.env` (см. `.env.example`). Локальная программа тоже его подхватит.

Ключ даёт доступ только к публичным логам. Закрытые отчёты программа не откроет.

## Интерфейс

- **Главное** — вы против медианы топа, что исправить первым, план тренировок, надёжность сравнения, разрыв DPS по факторам.
- **Ротация, Кулдауны и бурст, Дефенсивы, Uptime и ресурсы, Простой GCD** — подробные сравнения с графиками.
- **Таймлайн** — кулдауны, зелья и механики на общей оси и ваш DPS по времени.
- **Гайд эталона** — как топ играет этот бой.
- **Все отличия** — полный список.

Цвета везде одинаковые: янтарный — вы, бирюзовый — медиана топа, красный — отличие не в вашу пользу.

## Где хранятся данные

Всё, что относится к пользователю, хранится только у него в браузере, на том устройстве, где он работает:

| Что | Где |
| --- | --- |
| Ключ Warcraft Logs API | браузер (localStorage) |
| Список эталонов и настройки | браузер (localStorage) |
| История разборов и Excel-файлы, последние 40 | браузер (IndexedDB) |

Сервер только считает. Он получает запрос с ключом в заголовках, загружает данные из Warcraft Logs, отдаёт результат и Excel. Сразу после этого он их удаляет, а если браузер их не забрал — через час.
- Сервер не ставит cookie, не ведёт журнал запросов и ничего не пишет на диск. Это проверяет автотест.
- Для скорости публичный сервис держит в оперативной памяти общедоступные данные Warcraft Logs (бои лучших игроков). Это не данные пользователей, и при перезапуске они исчезают.
- Локальная программа хранит такой кэш в файле `wcl_cache.sqlite` на вашем же компьютере.

Блок **«Мои данные»** на главной странице:
- **«Сохранить в файл»** — резервная копия: эталоны, настройки, история с Excel и, по желанию, ключ. Пригодится при переходе на другое устройство или перед очисткой браузера.
- **«Загрузить из файла»** — восстановить или перенести данные; новые объединяются с уже имеющимися.
- **«Удалить все мои данные»** — стереть всё из этого браузера.

Важно: если очистить данные сайта в браузере, удалятся и ключ, и история. Делайте резервную копию.

### На другом устройстве

Кнопка **«На другом устройстве»** показывает QR-код, который собирается прямо в браузере. В нём ключ API, настройки и 2 последних эталона. Откройте его камерой телефона, и данные сохранятся в браузере телефона.
- Сервер эти данные не получает: они лежат в части ссылки после `#`, которую браузер не отправляет.
- QR-код с ключом не показывайте другим. Галочка «Передать ключ API» позволяет перенести только эталоны.
- Историю разборов и остальные эталоны переносите файлом: «Сохранить в файл» → «Загрузить из файла» на телефоне.

Чтобы открывать как приложение, добавьте страницу на главный экран:
- iPhone: «Поделиться» → «На экран Домой»;
- Android: меню браузера → «Добавить на главный экран».

## Обновление лучших логов

Каждое сравнение сохраняет свой эталон: босс, спек, сложность и дату рейтинга. Список виден на главной странице в блоке «Лучшие логи (эталоны)».

- Список эталонов хранится в браузере. **«Обновить»** у эталона или **«Обновить устаревшие»** заново скачивают рейтинг лучших игроков. Бои новых игроков загружаются, уже известные берутся из кэша, поэтому обновление недорогое по лимиту API.
- **«Обновить эталон и пересчитать»** в результате сравнения обновляет эталон и сразу заново сравнивает ваш лог.
- **«Считать устаревшим через»** — 1, 3, 7 или 14 дней, по умолчанию 3. Пока эталон свежий, сравнение берёт рейтинг из кэша; устаревший обновляется при следующем сравнении сам.
- **«Обновлять устаревшие при открытии программы»** (включено по умолчанию) — при открытии страницы устаревшие эталоны обновляются сами.

Из командной строки:
- `python -m wcl_analyzer refresh --list` — список эталонов;
- `python -m wcl_analyzer refresh` — обновить устаревшие;
- `python -m wcl_analyzer refresh --all` — обновить все;
- `python -m wcl_analyzer compare <ссылка> --refresh` — сравнить со свежим рейтингом.

Командная строка ведёт свой список эталонов в файле кэша на этом компьютере.

## Разобрать всех боссов

Отдельная кнопка **«Разобрать всех боссов»** (после «Найти бой»). Разбирает выбранного в списке «Игрок» на каждом боссе отчёта — последний килл, без киллов — лучший пулл. В списке «Игрок» есть пункт **«Все игроки (DPS)»**: тогда разбираются все DPS каждого боя (танки и лекари — нет: сравнение с топом идёт по урону). С «Разобрать игрока» пункт «Все игроки» запускает ротацию всего рейда для выбранного боя.

Эталон — топ-1, без второго эпохального эталона: так на один разбор уходит минимум запросов WCL. Сверху результата — панель **«Сводка» + вкладка на каждого босса** (она остаётся и в полном разборе, так что между боссами переключаются в один клик). Для одного игрока вкладка босса сразу открывает его полный разбор; для всех игроков «Сводка» — таблица игроки × боссы (разница с топ-1, клик по ячейке — полный разбор), вкладка босса — его игроки от самого большого отставания, а в полном разборе есть выбор игрока этого босса.

Перед каждым разбором программа проверяет остаток часового лимита WCL. Если его не хватит — разбор останавливается, готовое сохраняется, а сверху появляется **«Продолжить разбор»** с временем до сброса лимита. Продолжение дописывает оставшиеся разборы в тот же результат; уже скачанное берётся из кэша и лимит повторно не тратит. Все игроки на всех боссах — это десятки разборов: почти наверняка понадобится «Продолжить».

В «Сводке» для всех игроков есть колонка **«Средний отыгрыш (с учётом экип.)»** — среднее рейтинга WCL с учётом экипировки по всем боссам (только киллы; один запрос на бой), и фильтр «средний отыгрыш не выше / не ниже N».

Если часовой лимит WCL кончился, любой разбор останавливается с сообщением о времени до сброса (ждать сброса — только с галочкой «Кончится лимит — ждать и продолжать»). Запросы одинаковы во всех режимах, поэтому после «Разобрать всех боссов» «Разбор ротации рейда» и «Разобрать игрока» по тому же бою берут данные из кэша и докачивают только события нанесённого урона.

Экономия лимита: общие данные боя (смерти, касты босса, экипировка и таланты, дебаффы на боссе) скачиваются один раз на всех игроков боя (так же и в «Разборе ротации рейда»); события нанесённого урона в этом режиме не скачиваются — нет только оценки прироста DPS от кулдаунов. Галочка **«Кончится лимит — ждать и продолжать»**: вместо остановки программа дождётся сброса часового лимита и продолжит сама — можно оставить на ночь.

## Разбор ротации рейда

Кнопка **«Разбор ротации рейда»** сравнивает каждого DPS выбранного боя с топом его спека — сразу всех, а не по одному. Эталон собирается один раз на спек: если в рейде два одинаковых спека, топ скачивается один раз. Танки и лекари пропускаются: сравнение ротации рассчитано на урон.

**Отбор по рейтингу с учётом экипировки.** В списке «Кого брать в ротацию рейда» можно разобрать не всех, а только тех, кому это нужнее: «Рейтинг с учётом экипировки ≤ 50%» — порог любой от 1 до 99 (готовые варианты: 25, 50, 75, 90). Это место игрока среди игроков его спека с таким же уровнем предметов (из рейтингов Warcraft Logs), поэтому разница в экипировке не мешает. Сразу видно, сколько игроков подходит. Чем меньше игроков, тем быстрее разбор и меньше расход лимита API. У вайпов рейтингов нет — тогда разбираются все DPS. Обычный процентиль и рейтинг с учётом экипировки показаны и в списке игроков, и в таблице результата, и в Excel.

Сверху — «Главное по рейду»: медиана отставания от топа, кто дальше всех от своего топа, проблемы, общие для нескольких игроков («Простой больше, чем у топа — у 3 из 5»), и рейдовые дебаффы, которых не хватало всем. Ниже — график отставания по игрокам и таблица с главным действием для каждого; «Подробно» открывает полный разбор игрока. В Excel: лист «Ротация рейда», лист «Что исправить» (до трёх действий на каждого) и выжимка на каждого игрока.

Логи скачиваются параллельно, по 4 запроса одновременно (переменная окружения `WCL_PARALLEL`), поэтому сбор эталона идёт примерно в 3–4 раза быстрее. Размер эталона — топ-1, топ-3 или топ-10 (по умолчанию) — выбирается в списке «Сравнить с»; он же используется для разбора ротации рейда. Во время разбора видно, сколько примерно осталось, а в журнале — сколько очков API осталось в этом часе.

Первый запуск по рейду долгий: на каждый спек скачиваются бои топа (около 11 запросов на лог). Для рейда из 14 DPS разных спеков при Top 10 это около 1500 запросов и десятки минут; повторные запуски идут из кэша. Если лимит очков API закончится, программа подождёт его сброса и продолжит сама.

## Разбор всего рейда

Сверху — блок «Главное по бою»: с чего начался вайп, пики урона без кулдаунов лекарей, пропущенные прерывания, избегаемый урон, расходники на пулле, кто не бил аддов, и по одному главному пункту на игрока. Всё остальное — в «Подробностях».

Под этим блоком — график **«Когда рейд получает больше всего урона»**: урон по рейду без танков за каждые 5 секунд, красные точки — самые тяжёлые моменты, треугольники — рейдовые кулдауны (цвет — роль игрока, красная обводка — кулдаун нажат вне пиков урона). В подробностях — таблицы «Самые тяжёлые моменты» (урон, механики, какие кулдауны их перекрыли) и «Рейдовые кулдауны» (кто и когда нажал, попал ли на пик, сколько урона рейд получил за 10 с после). То же есть в Excel на листе «Урон по рейду».

Рейдовые кулдауны определяются по списку известных способностей (Power Word: Barrier, Spirit Link Totem, Tranquility, Aura Mastery, Revival, Rewind, Rallying Cry, Anti-Magic Zone, Darkness и др.) и по логу: способность лекаря, которую он жмёт не чаще раза в 1,5 минуты.

### Против лучших киллов и план кулдаунов

При разборе рейда программа скачивает 5 лучших киллов этого босса по скорости и сравнивает пики урона по механике и её номеру («Ледяная волна» №3), а не по секундам: у разных рейдов разный темп. Видно, какую долю пиков топ закрывает рейдовыми кулдаунами и какими, и где у вас пик прошёл без кулдауна. На графике урона полыми треугольниками отмечены кулдауны лучших киллов.

**План рейдовых кулдаунов на следующий пулл** расставляет кулдауны, которые ваш рейд нажимал в этом бою, на пики урона: за 1–5 с до удара, с учётом перезарядки; если топ на этот пик жмёт тот же кулдаун, он помечен «как у топа». Для вайпа план продолжается на пики, до которых рейд не дошёл (по таймингам лучших киллов). Перезарядки известных кулдаунов заданы приблизительно; если в логе кулдаун жали чаще — берётся интервал из лога.

Во вкладке «Пуллы» — таблица «От чего умирает рейд по пуллам», в выжимке — какая механика убивает чаще всего и стало ли лучше к последним пуллам.

Сравнение с топом стоит примерно 5–8 запросов к API на каждый килл; если рейтинг недоступен, разбор рейда работает без него.

Избегаемые механики задаются списком в `spell_meta.json` (поле `_avoidable`, ID или названия), см. `spell_meta.example.json`.

После «Найти бой» нажмите **«Разбор рейда: урон, сейвы, смерти»**: программа разберёт выбранный бой по всем игрокам. Это около 10 запросов к API плюс по одному на каждый пулл: быстрее, чем сравнение одного игрока с топом.

| Вкладка | Что показывает |
| --- | --- |
| Обзор | «Что проверить» по игрокам, бой в цифрах (Bloodlust, активное время, зелья, камни, прерывания), DPS игроков |
| Игроки | DPS/HPS, parse, активное время, смерти, зелья и камни, прерывания и диспелы, урон от выборочных механик; кнопка «Сравнить с топом» запускает разбор этого игрока против топа его спека |
| Механики | Кто сколько получил от выборочных механик (тепловая карта), кто получил больше всех от общих механик, все способности босса |
| Смерти | Смерти и механики на одной оси; причина, урон за 5 с и последние действия перед смертью |
| Пуллы | Все попытки на этом боссе: HP босса в конце, смерти, кто умер первым и от чего |

Excel по рейду содержит те же разделы; DPS, HPS и «× среднего» посчитаны формулами.

Как программа делит механики:
- **По всему рейду** — за одно применение задевает больше 60% рейда;
- **По танкам** — 70% урона и больше приходится на танков;
- **Выборочно** — всё остальное.

Выборочный урон бывает избегаемым («лужи») и назначенным (луч в случайного игрока), а логи их не различают. Поэтому программа показывает, кто получил больше остальных, а какая это механика — решать вам.

Пороги для «Что проверить» заданы в начале `wcl_analyzer/raid.py`:
- активное время ниже 85% и ниже медианы рейда;
- урон от выборочных механик от 2× среднего;
- урон от общей механики от 1,35× медианы;
- parse ниже 25%;
- смерти в последние 15 с вайпа считаются концом попытки.

Из командной строки: `python -m wcl_analyzer raid <ссылка>` или `python -m wcl_analyzer raid --demo`.

Под планом — зелёная кнопка **«Скопировать для MRT»**: заметка для Method Raid Tools (в игре /mrt → Заметки → вставить → Отправить). Механика босса и кулдауны в ней — иконками (`{spell:id}`), имена — в цветах классов, время — от пулла или от начала фазы (`{time:0:15,p2}`); номера фаз сверьте с вашим босс-модом.

## Командная строка

Всё то же доступно без браузера — командная строка запускает те же разборы, что и приложение, и сохраняет те же Excel. Зависимости: `pip install -r requirements.txt`.

### Команды

Все команды запускаются из папки проекта.

| Команда | Что делает |
| --- | --- |
| `python -m wcl_analyzer` | Открыть интерфейс в браузере |
| `python -m wcl_analyzer raid <ссылка>` | Разбор всего рейда в бою, с планом сейвов (`--no-mythic` — без эпохальных киллов) |
| `python -m wcl_analyzer raidrot <ссылка>` | Разбор ротации рейда (`--ref top10`, `--pick rank:50` — только игроки с процентилем до 50%) |
| `python -m wcl_analyzer refresh` | Обновить устаревшие эталоны (`--all` — все, `--list` — список) |
| `python -m wcl_analyzer demo` | Прогон на синтетических данных без ключа — чтобы посмотреть отчёт |
| `python -m wcl_analyzer compare <ссылка>` | Главный режим: ваш лог против эталона |
| `python -m wcl_analyzer guide --encounter ID --class Mage --spec Frost` | Гайд эталона без своего лога |
| `python -m wcl_analyzer bosses --zone 53` | Список боссов рейда и их ID |
| `python -m wcl_analyzer limit` | Сколько очков API потрачено за час |

#### compare: параметры

```
python -m wcl_analyzer compare "https://www.warcraftlogs.com/reports/КОД#fight=12&source=5"
```

- Если в ссылке нет `fight=`, берётся последний килл в отчёте.
- Если нет `source=`, укажите персонажа: `--player Имя`.
- `--ref top1 | top3 | top10` — эталонная группа, по умолчанию `top10`. Все метрики эталона — медианы по выбранным логам.
- `--against <ссылка>` — сравнить с конкретным игроком вместо топа.
- `--no-mythic` — не сравнивать дополнительно с эпохальным топом (иначе для неэпохального боя сохраняется второй Excel).
- `--out файл.xlsx` — имя отчёта.

Рейдовые кулдауны спеков (откат, сила, как узнать нажатие) и способности жажды крови — в одном файле `wcl_analyzer/data/game_data.json`. Программа берёт его из репозитория (раз в сутки), поэтому к новому патчу достаточно поправить этот файл на GitHub — пересобирать APK и .exe не нужно. Без интернета используется копия из сборки.

Эталон подбирается автоматически: тот же босс, сложность, класс и спек. Сложность проверяется для каждого скачанного боя топа: если в рейтинг попал бой другой сложности, он пропускается (это видно в журнале), а в шапке разбора написано, что все логи эталона той же сложности, что и ваш бой. Лучшие киллы для сравнения рейдовых кулдаунов тоже берутся только на вашей сложности.

**Два эталона: ваша сложность и эпохальный топ.** Если бой не эпохальный, игрок сравнивается сразу с двумя эталонами: с топом своей сложности (основной) и с эпохальным топом. Переключатель «Топ: героический / Топ: эпохальный» — в шапке разбора; для каждого эталона свои вкладки, таланты, рейдовые кулдауны в пики урона и свой Excel. Отключается галочкой «Также сравнить с эпохальным топом» (второй эталон — это вдвое больше загрузок). В разборе ротации рейда эпохальный топ показан колонкой «К эпох. топу»: она считается по DPS из рейтинга, без скачивания логов — один запрос на спек. Если сложность боя определить не удалось, эталон не собирается — иначе Warcraft Logs отдал бы эпохальный рейтинг. Сначала берутся бои с длительностью ±10% от вашего, если их мало — ±20%, затем любые. Использованное окно указано в названии эталона.

## Полученный урон и сейвы рейда

В разборе **«Разбор рейда: урон, сейвы, смерти»** — вкладка **«Полученный урон и сейвы»** (на «Обзоре» эти блоки больше не повторяются):

- график урона по рейду с пиками и нажатыми рейдовыми кулдаунами;
- **план сейвов на следующий пулл** — по составу рейда: у каких классов и спеков какие рейдовые кулдауны (с учётом взятых талантов, если они есть в логе), их перезарядка; кулдаун ставится за 1–5 с до пика и не раньше, чем откатится; сколько сейвов ставить на пик (до трёх, разных игроков) — по тому, сколько на этот пик жмут лучшие гильдии, по тяжести пика и по тому, умер ли кто-то в этот пик в вашем бою; если лучшие гильдии жмут определённый кулдаун и он есть в составе — берётся он; для каждого — когда он снова будет готов; для каждого пика — запасные варианты: что ещё откатано к этому моменту и не сломает остальной план;
- пики урона: что нажал ваш рейд и чем закрывают те же пики лучшие киллы — вашей сложности и (переключателем) эпохальные;
- самые тяжёлые моменты боя и таблица кулдаунов состава: откат, сколько раз нажат, сколько раз можно было нажать за бой.

## Обновление программы

После каждой сборки GitHub публикует выпуск (вкладка **Releases** репозитория) с прямыми ссылками — без входа в GitHub и без zip: `WCL-Analyzer.apk` для телефона и `WCL-Analyzer.exe` для ПК.

Установленная программа обновляется сама: внизу страницы — версия и кнопка **«Проверить обновления»** (проверка идёт и сама, раз в сутки; если есть новая сборка, в шапке появляется «Доступно обновление»).

- **Обычно меняется только код** (анализ, вкладки, таблицы) — программа скачивает его внутрь себя за несколько секунд, без переустановки. На ПК программа перезапустится сама, на телефоне — закройте приложение и откройте снова. Ключ API, история и эталоны сохраняются.
- **Если изменилась «оболочка»** (версия Python, библиотеки, настройки сборки) — нужна новая программа целиком: .exe скачивается и заменяет себя сам, на телефоне APK открывается для установки поверх.
- Если скачанный код почему-то не запустится, программа сама вернётся к встроенной версии.
- Если сервер файлов GitHub недоступен с вашего устройства (у некоторых провайдеров так бывает), программа берёт номер версии и код через jsDelivr — бесплатное зеркало файлов GitHub. Если недоступно всё, она напишет, какой адрес не ответил.

## Лимит запросов Warcraft Logs

В правом верхнем углу — «Лимит WCL 2 870 / 3 600 · сброс 23 мин»: сколько очков API потрачено в этом часе, сколько разрешено вашему ключу и когда счётчик обнулится. Точка зелёная до 60% лимита, жёлтая до 90%, красная выше. Обновляется раз в минуту, во время разбора — примерно раз в 20 секунд и сразу после разбора; таймер тикает сам.

## Разбор игрока в программе

Сверху — выжимка: три действия на следующий бой и строка про таланты.

### Подробности

В «Подробностях» вкладки:

- **Сравнение ротации** — касты против медианы топа, опенер, приоритеты при проках, простой между действиями, частые связки.
- **Кулдауны и бурст** — сколько раз нажаты кулдауны, тайминги против топа, окна бурста.
- **Экипировка** — уровень предметов по слотам, зачарования и камни против топа.
- **Таланты** — сравнение билда со всеми скачанными логами топа по трём веткам: дерево класса, дерево специализации и героическая ветка (таланты героической ветки сравниваются только с игроками топа той же ветки); какие таланты у топа почти у всех, а у вас нет; где в узле выбора вы взяли другой вариант; что у вас есть, а у топа редко; какая героическая ветка у топа. Для каждого отличия — медианный DPS игроков топа с этим талантом и без него. Названия талантов берутся из открытого справочника Raidbots: он скачивается один раз и хранится на устройстве неделю.

Остальные подробности (эффекты, защита, таймлайн, гайд эталона, все отличия) — в Excel-отчёте.

## Как читать результаты

Сначала программа показывает **выжимку**: на сколько вы ниже медианы топа, три действия на следующий бой и что от вас не зависит (рейдовые дебаффы на боссе, внешние баффы). Таблицы, графики и все отличия свёрнуты в блок «Подробности». Если вы уже разбирали этого персонажа на этом боссе, сверху появится строка «Прогресс»: как изменился DPS и какие отличия исчезли. История для неё берётся из вашего браузера.

### Как считается анализ

- **Смерть.** Все показатели считаются по времени, когда вы были живы. Смерть — отдельный пункт: её цена равна доле боя, проведённой мёртвым. Если вас воскресили, время после воскрешения снова учитывается.
- **Шумовой порог.** Каждый игрок топа сравнивается с остальными. Если такое же отличие часто встречается у самих лучших, оно не попадает в выжимку и помечается серым в подробностях.
- **Честная оценка влияния.** Недостающий каст оценивается как урон сверх филлера, который вы жали вместо него. Касты сравниваются на минуту активного каста, поэтому простой и потерянные проки не считаются дважды. Сумма оценок не превышает реальный разрыв с топом.
- **Простой GCD.** Не считаются: время смерти, паузы, общие для большинства топа (фазы без цели, переходы), и каналы. GCD оценивается по 30-секундным отрезкам, поэтому Bloodlust и баффы хасты учтены.
- **Заряды и каналы** определяются по логам топа; их можно задать вручную в `spell_meta.json`.
- **Опенер** сравнивается с выравниванием последовательностей: один пропущенный каст не сдвигает весь опенер.
- **Приоритеты.** Программа находит правила вида «при активном проке X топ жмёт Y в 85% случаев» и сравнивает с вашим логом.
- **Тайминги кулдаунов** считаются от начала фазы, если топ привязывает их к фазе. Программа также подсказывает, под что топ придерживает кулдаун: окно уязвимости или начало фазы.
- **Дебаффы на боссе.** Учитываются все дебаффы на боссе, а не только ваши: свои (DoT и т. п.), рейдовые (например, от охотника на демонов или монаха) и окна уязвимости, во время которых топ держит бурст. Нехватка рейдового дебаффа показывается как «не зависит от вас».
- **Ресурс.** Потери считаются точно по событиям ресурса WCL (поле waste); если их нет — по доле кастов у предела.
- **Билд.** Если в логах есть таланты, эталон строится по игрокам топа с похожим билдом.
- **Самопроверка.** В надёжности сравнения отмечаются расхождение профиля целей (касты по аддам), DPS рейтинга против расчёта по таблице урона, другой билд и отсутствующие рейдовые дебаффы.

### Пункты отчёта

- **Отличие — не вердикт.** Программа показывает факт расхождения с большинством топа и контекст.
- **Impact** — оценка доли вашего DPS, которую можно вернуть: HIGH от 3%, MEDIUM 1–3%, LOW меньше 1%. Если влияние нельзя посчитать из лога, стоит Unknown. Такие отличия сортируются по величине отклонения.
- **DPS gap** раскладывается только по измеримым факторам. Экипировка всегда помечена как Possible contributor, а остаток показан отдельной строкой.
- **Надёжность сравнения** (HIGH / MEDIUM / LOW) — минимум по критериям: длительность, число логов, ilvl, совпадение таймингов механик, Bloodlust, давность отчётов.
- **Доверие** в эталоне — нижняя граница 95% интервала Уилсона: 18 из 20 игроков дают около 70%, 7 из 20 — около 18%.

## Категории способностей и spell_meta.json

Warcraft Logs не сообщает, какой способностью является кулдаун или дефенсив. Программа определяет это по логам топа:

- зелья, Bloodlust и расовые способности — по названию;
- кулдаун — если минимальный интервал между кастами у топа не меньше 25 с;
- offensive — если топ жмёт его в первые 20 с боя;
- defensive — если за нажатием обычно следует крупный входящий удар;
- прок — частый бафф на себе, который снимается одной и той же способностью.

Если категория определилась неверно (часто это тринкеты), скопируйте `spell_meta.example.json` в `spell_meta.json` и задайте её вручную. Колонка «Источник» на листе «Эталон» показывает, откуда взята категория.

## Кэш и лимиты API

- Каждый ответ API сохраняется в `wcl_cache.sqlite`, поэтому повторный запуск не тратит очки. Рейтинги лучших логов живут в кэше, пока эталон не устарел (по умолчанию 3 дня), — см. «Обновление лучших логов».
- Эталон Top 25 требует около 9 запросов на игрока. Первый запуск по новому боссу и спеку занимает несколько минут, повторные идут из кэша.
- При исчерпании лимита программа ждёт его сброса и продолжает сама.

## Ограничения MVP

- Программа проверена на синтетических событиях в формате WCL API: в среде разработки сайт Warcraft Logs был недоступен. При первом реальном запуске стоит проверить на одном бою, что заполнились листы «Дефенсивы» и «Uptime». За них отвечают фильтры событий `DamageTaken` и `Debuffs` в `logs.py`, функция `fetch_raw`.
- Разбор рейда использует поля `killingAbilityGameID`, `potionUse`, `healthstoneUse` и `activeTime` из ответов WCL. Если какое-то из них в реальном API называется иначе, соответствующая колонка останется пустой: пришлите вывод программы, и я поправлю.
- Не реализованы модели AoE/cleave/execute, анализ движения и replay.
- Таланты берутся из поля `talentTree` события CombatantInfo, потери ресурса — из событий `Resources` (поле `waste`), фазы — из `phaseTransitions`. Если в реальном логе этих данных нет, программа работает без них и не фильтрует эталон по билду.
- Для классов со сменой цели сравнение uptime дебаффов считается только по основной цели (боссу).
